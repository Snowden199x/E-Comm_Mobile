# Buyer app

The Vendo Buyer mobile app reads `GET /api/v1/buyer/*` with a stored bearer token and signs in with email/password or Google. Orders, one order's tracking detail, and notifications each cache their last successful payload on the device through `OfflineStore` (`lib/core/offline/offline_store.dart`), which lives in the same encrypted storage as the login token.

When the API cannot be reached, Orders, Order tracking, and Notifications fall back to that saved payload and show an "Offline — showing saved details" banner naming when the data was saved, with a Retry action. A Buyer never sees an empty error page for data the phone already has.

Small, safe account writes are queued in an outbox and uploaded automatically: marking all notifications read is kept on the device and flushed later. Placing an order is deliberately never queued — stock, vouchers, the COD amount, and the delivery route must be confirmed by Vendo before an order exists.

The four-tab shell is Home, Saves, Notification and Profile. Its bottom bar is its own widget, `lib/features/home/widgets/buyer_nav_bar.dart` (`BuyerNavBar`), which only takes the selected index and reports taps. It uses the Rider dashboard's look and motion: a mostly transparent (60% white) frosted bar, fully rounded and lifted off the bottom edge with a soft shadow, plus one dark pill that stretches toward the tapped tab, hops slightly and settles with an elastic bounce. It shows icons only — the tab name lives on the button's `Semantics` node instead of as text, which keeps the bar short. The shell's `Scaffold` sets `extendBody: true`, so each tab's content runs behind the bar and stays visible through it; the three scrolling tabs (Home, Saves, Profile) reserve `kBuyerNavBarClearance` at the bottom so their last row can still be scrolled clear, while the pushed copy of Saved Items leaves it out because no bar covers it. The tab change fires a selection haptic, and Home is the destination a back press returns to. The Notification tab is still a placeholder.

`OfflineSyncService` watches `connectivity_plus` events, retries queued work every 45 seconds while anything is pending, and retries on app start, so a queued action uploads without the Buyer reopening a screen. Entries the server can no longer accept (4xx) are dropped so one stale action cannot block the rest, and logging out clears both the cache and the outbox.

The Profile tab is the account area. Personal Information and Delivery Address read and write the shared `/api/v1/buyer/account` record (name, phone, province, municipality, barangay, street, house number and ZIP), and the profile photo uses `POST /api/v1/buyer/account/photo`, so the app and the web account page show the same details. Change Password uses `PUT /api/v1/buyer/account/password`. My Orders opens on All or on the To Ship, To Receive and To Review groups from `GET /orders?group=...`; a completed order lets the Buyer rate each unreviewed product once. My Vouchers, My Reviews and Help & FAQ read `GET /vouchers`, `GET /reviews` and `GET /help`; Terms and Privacy read `GET /legal/terms|privacy`, the same documents the web serves. Rate the App keeps a rating on the device only and clears it on sign-out.

The home search bar opens `SearchResultsScreen`. Typing there searches both products (`GET /api/v1/buyer/products?search=...`) and shops (`GET /api/v1/buyer/sellers?search=...`) after a short debounce. Results are grouped into Shops and Products, each shop opens `ApiSellerScreen`, each product opens the normal API detail page, and a Recommended for you row stays visible below the matches. An empty query shows Popular searches from the storefront categories plus recommended products from `GET /api/v1/buyer/home`.
