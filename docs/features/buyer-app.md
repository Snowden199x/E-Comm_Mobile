# Buyer app

The Vendo Buyer mobile app reads `GET /api/v1/buyer/*` with a stored bearer token and signs in with email/password or Google. **Continue with Google** (13 November 2026) sends the Google ID token from `google_sign_in` to `POST /api/v1/buyer/google`; the API verifies it and applies the same buyer-role and approval checks as `POST /login`, storing the same session. A Google email with no Buyer account is told to register in the app, because registration still needs a valid ID, birthdate and address. `lib/core/config/google_auth_config.dart` defaults to the same public web client ID the website uses and still accepts `--dart-define=GOOGLE_WEB_CLIENT_ID=...` for another Google Cloud project. The Android OAuth client for package `com.example.vendo_buyer` with this build's signing SHA-1 must exist in that project, or Google rejects the request before the app sees a token. Google sign-in is unavailable on Windows/Linux desktop. Orders, one order's tracking detail, and notifications each cache their last successful payload on the device through `OfflineStore` (`lib/core/offline/offline_store.dart`), which lives in the same encrypted storage as the login token.

When the API cannot be reached, Orders, Order tracking, and Notifications fall back to that saved payload and show an "Offline — showing saved details" banner naming when the data was saved, with a Retry action. A Buyer never sees an empty error page for data the phone already has.

Small, safe account writes are queued in an outbox and uploaded automatically: marking all notifications read is kept on the device and flushed later. Placing an order is deliberately never queued — stock, vouchers, the COD amount, and the delivery route must be confirmed by Vendo before an order exists.

Home, Saved, Notifications, product detail and shop pages share one card language: square product photos with a discount badge and save heart, plum price with the crossed-out original, sold count, and the shop/location line, in two staggered columns. The product page adds a photo-dot gallery, variant selection, an expandable description/specifications block, a shop card, related products and a sticky add-to-cart bar. The Home grid opens with a tall banner carousel in its left column (`_TallBannerCarousel` in `lib/features/home/screens/home_screen.dart`) showing `assets/images/ads_1.jpg`, `ads_2.jpg` and `ads_3.png` cropped to fill, auto-advancing every 4.5 s with a shopper's swipe restarting the countdown. The banners are the only ads that are bundled rather than fetched: swapping the artwork means replacing those three files (names are referenced in the code, two of them are `.jpg`) and the carousel picks them up on the next build. Its tile is one grid column wide and 1.25× a product card tall, so a poster whose text sits near the very top or bottom will be cropped by `BoxFit.cover`.

The four-tab shell is Home, Saves, Notification and Profile. Its bottom bar is its own widget, `lib/features/home/widgets/buyer_nav_bar.dart` (`BuyerNavBar`), which only takes the selected index and reports taps. It uses the Rider dashboard's look and motion: a mostly transparent (60% white) frosted bar, fully rounded and lifted off the bottom edge with a soft shadow, plus one dark pill that stretches toward the tapped tab, hops slightly and settles with an elastic bounce. It shows icons only — the tab name lives on the button's `Semantics` node instead of as text, which keeps the bar short. The shell's `Scaffold` sets `extendBody: true`, so each tab's content runs behind the bar and stays visible through it; the three scrolling tabs (Home, Saves, Profile) reserve `kBuyerNavBarClearance` at the bottom so their last row can still be scrolled clear, while the pushed copy of Saved Items leaves it out because no bar covers it. The tab change fires a selection haptic, and Home is the destination a back press returns to.

The Notification tab is API-backed. `NotificationsScreen` reads `GET /notifications` (with `filter=unread` for its Unread tab) and `POST /notifications/{id}/read`, shows All and Unread tabs with an unread count and a Mark all read action, lists parcel-progress updates apart from other notifications, marks a row read when it is opened, and polls every 30 seconds while the tab is active. The last page is cached for offline reading, and marking all read while offline is queued in the outbox. Notification polling is not push: a closed app receives nothing.

App start is the animated `SplashScreen`: a `CustomPainter` story about 8.2 seconds long (person, vending machine, coin, logo reveal) drawn without extra packages. It always plays in full — there is no skip — then opens Home or Login depending on the stored token.

`OfflineSyncService` watches `connectivity_plus` events, retries queued work every 45 seconds while anything is pending, and retries on app start, so a queued action uploads without the Buyer reopening a screen. Entries the server can no longer accept (4xx) are dropped so one stale action cannot block the rest, and logging out clears both the cache and the outbox.

The Profile tab is the account area. Personal Information and Delivery Address read and write the shared `/api/v1/buyer/account` record (name, phone, province, municipality, barangay, street, house number and ZIP), and the profile photo uses `POST /api/v1/buyer/account/photo`, so the app and the web account page show the same details. Change Password uses `PUT /api/v1/buyer/account/password`. My Orders opens on All or on the To Ship, To Receive and To Review groups from `GET /orders?group=...`; a completed order lets the Buyer rate each unreviewed product once. My Vouchers, My Reviews and Help & FAQ read `GET /vouchers`, `GET /reviews` and `GET /help`; Terms and Privacy read `GET /legal/terms|privacy`, the same documents the web serves. Rate the App keeps a rating on the device only and clears it on sign-out.

The home search bar opens `SearchResultsScreen`. Typing there searches both products (`GET /api/v1/buyer/products?search=...`) and shops (`GET /api/v1/buyer/sellers?search=...`) after a short debounce. Results are grouped into Shops and Products, each shop opens `ApiSellerScreen`, each product opens the normal API detail page, and a Recommended for you row stays visible below the matches. An empty query shows Popular searches from the storefront categories plus recommended products from `GET /api/v1/buyer/home`.
