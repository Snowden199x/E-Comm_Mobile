# Progress — 1 November 2026

## Driver home screen improvements

- `vendo_driver/lib/features/dashboard/screens/driver_home_screen.dart`:
  - The header now carries two translucent chips under the greeting: today's date (`fullDateLabel`) and the assigned vehicle with its plate. Both use the Lin icon on the header tint, and the vehicle chip ellipsizes on narrow screens.
  - The avatar is tappable and opens Profile (tab 4), with a tooltip and a 44 px target.
  - The hub/company subtitle skips blank parts instead of rendering a stray `·`, and the greeting falls back to *Driver* when the profile has no name yet.
  - New `_LicenceNotice` above the stats when the licence expires within 30 days, is already expired, or has no expiry on file (the API maps a missing date to 1970). Amber for *soon*, red for *expired*, with a **View** action that opens Profile. This matches the server rule that an expired licence blocks sign-in and dispatch.
  - The current trip card replaced the plain parcel count row with `_ScanProgress`: `X of Y scanned` at the origin before departure, `X of Y received` at the destination while in transit, a 6 px `LinearProgressIndicator` in green when complete, plus one sentence naming the hub where the scans are outstanding.
- Docs: the Home row in `docs/features/driver-app.md` describes the new header, warning and progress bar.

**Verified:** `flutter analyze lib/features/dashboard/screens/driver_home_screen.dart` → No issues found. No device run or widget test was performed; the user still owns layout review on a phone.

**Known gaps**

- Everything on Home still reads the in-memory demo store; trips are not API-backed, so the progress counts are demo values.
- The licence warning has no renewal upload flow; it only points at Profile and the hub.

## Driver bottom navigation on the Rider design

- Rebuilt `vendo_driver/lib/features/dashboard/widgets/driver_bottom_nav.dart` on the Rider dashboard navigation: a floating, fully rounded bar lifted 10 px off the bottom edge with a soft shadow, a `BackdropFilter` frosted-glass surface (`0xB3FFFFFF` with a `0x33412143` border) and the same sliding "jelly" pill. The pill stretches while it travels (leading edge ahead, trailing edge on an `ElasticOutCurve`) and squashes slightly mid-trip, and the icon under it fades from muted grey to white.
- Icons only, like the Rider bar, with `Semantics` labels kept for accessibility and a scale `AnimatedSwitcher` between the outlined and filled icon. Selection haptics moved into the bar itself.
- The public API is unchanged (`DriverBottomNav(index:, onSelected:)` and `driverNavItems`), so `driver_shell.dart` did not need a change. The five tabs stay Home, Trips, Manifest, Earnings and Profile.
- `driver_shell.dart` keeps `extendBody` off, so page content still stops above the bar; the glass blurs the app background. There is no notification tab in the driver app, so no unread badge is drawn.
- Docs: `docs/features/driver-app.md` now describes the bar.

**Verified:** `flutter analyze lib/features/dashboard` → No issues found. No device run or widget test was performed; the pill animation and the frosted surface still need owner review on a phone.

**Known gaps**

- Because the body does not scroll behind the bar, the blur has only the page background behind it when the list ends, not card content.
- No badge support, since the driver app has no notification tab yet.

## Email OTP verification on driver registration

- `vendo_driver/lib/features/auth/screens/driver_register_screen.dart`: replaced the inline *Email code* field with the Rider / Buyer verification sheet. The Email label now carries a **Verify** link that opens `_VerifyEmailModal`, a bottom sheet with six digit boxes that sends `POST /email/otp/send` as soon as it opens, moves the cursor between boxes, checks the code automatically once all six digits are in, offers **Resend Code**, and returns the `verification_token` from `POST /email/otp/verify`.
- The email field shows a green *Verified* mark in the label row once the token is set; editing the email clears it again. The helper line under the field names the code step, and turns red when Step 1 is blocked because the email is not verified yet.
- Removed the now-unused `_emailCode` controller, `_sendingCode`, `_verifyingCode`, `_sendCode` and `_verifyCode`. The `emailVerify` check in `_invalidIds`, the token sent with `register()` and the existing `362` pending/rejected handling are unchanged.
- `vendo_driver/lib/features/auth/widgets/register_widgets.dart`: `RegInput` gained an optional `labelAction` widget shown on the label row, used for the Verify link and the Verified mark.
- Docs: `docs/features/driver-app.md` now describes the sheet, the endpoints and the blocked step.

**Verified:** `flutter analyze` in `vendo_driver` → No issues found for the two changed files. No device run or widget test was performed; the sheet, the emailed code and the resend behavior still need owner testing.

**Known gaps**

- No resend cooldown timer; the link can be tapped again immediately, and the server's own rate limit is what stops abuse.
- The six boxes use one digit each, so a pasted six-digit code only fills the first box.

## Driver sign-in screen on the Rider layout, with a truck in the header

- Rebuilt `vendo_driver/lib/features/auth/screens/driver_login_screen.dart` on the Rider app's
  sign-in screen: prune gradient header, `_HeaderAmbientPainter` background (drifting circles,
  pulsing rings, twinkling stars, floating dots, wind streaks), the entrance animation that glides
  the header picture into place while the white card slides up and the welcome text fades in, and the
  same rounded card, labelled fields, `Forgot password?` row, prune button, "or" divider, outlined
  secondary action and register link at the bottom.
- The header picture is a new `_TruckPainter` instead of the Rider's motorcycle: a box truck facing
  right with a brique canvas body, panel seams, a white "V" on the brique band, cab with windshield
  and driver silhouette, headlight glow, chassis rail and spoked gold wheels. It is drawn in a
  160 x 120 box and scaled to 140 x 105 in the header.
- Driver-only behaviour is unchanged and still on the screen: `DriverApi.login` sign-in and session
  seeding, the pending-hub and rejected notices, `ForgotPasswordScreen` with the email pre-filled,
  the *Check application status* sheet, the register link and the approval note.
- `DriverLoginScreen` takes an optional `animateEntrance` flag (defaults to true) so the glide can be
  skipped when the screen is opened after signing out. `driver_profile_screen.dart` now passes
  `animateEntrance: false` on sign-out, so the header opens settled.
- Removed the old `_BrandHeader` and `_FieldLabel` widgets from this file; the card's own `_Label`
  and `_InputField` replace them.

**Crash fix:** the red `LateInitializationError: Field '_enter' has not been initialized` screen came
from a hot reload. The `late final` animation controllers were assigned in `initState`, which does
not run again for a `State` that was already on screen, so the rebuilt widget tree read an
uninitialized field. `_enter` and `_ambient` are now created lazily through getters (nullable
backing fields, `?.dispose()`), and `_requestEntrance()` is called from `build` as well as
`initState`, so a surviving screen animates in instead of staying blank. The truck overlay also
falls back to `Offset.zero` (its settled spot) until the entrance is measured.

**Verified:** `flutter analyze lib/features/auth/screens/driver_login_screen.dart` → No issues found.
No build, device run or widget test was performed; the truck drawing and the animation still need
owner review on a phone.

**Known gaps**

- The truck picture is static (wheels at rest); there is no wheel spin or exhaust effect.
- The glide-in starts from 36% of the screen height, matching the Rider screen. A signed-out
  profile now passes `animateEntrance: false`, so the truck is already in the header there.
