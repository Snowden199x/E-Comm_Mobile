# Progress — 14 November 2026

## Rider and Transport Driver merged into one app

The two apps answered the same question — which account is this — from two different login screens. The Rider screens are now the single entry point, and the Transport Driver screens moved into `vendo_rider` beside them.

### Folder structure

- `vendo_rider/lib/features/` is gone; the Rider screens moved to `vendo_rider/lib/rider/` with `git mv`, so history follows them: `rider/auth/`, `rider/dashboard/`, `rider/scanner/`, `rider/splash/`, `rider/transport_driver/`.
- The Transport Driver screens live in `vendo_rider/lib/driver/` with their own `driver/core/` (api, data, theme, utils, config): `driver/auth/`, `driver/dashboard/`, `driver/earnings/`, `driver/notifications/`, `driver/profile/`, `driver/shared/`, `driver/trips/`.
- The Rider's shared code stays at `lib/core/`, so nothing is shared implicitly: both trees keep the files that happened to have the same name (forgot-password screen, Google client config, theme, phone formatter) and the driver copy no longer resolves against `package:vendo_driver`.
- Every import in `lib/` was rewritten (`package:vendo_rider/features/` → `package:vendo_rider/rider/`, `package:vendo_driver/…` → `package:vendo_rider/driver/…`). The Rider `pubspec.yaml` already carried every package the driver screens use (`http`, `google_sign_in`, `flutter_secure_storage`, `image_picker`, `mobile_scanner`), so no dependency was added.

### Shared login and routing

- `rider/auth/screens/login_screen.dart` keeps its rider-first order: `POST /api/v1/rider/login`, and on the 401 a driver account gets there, the same credentials go to `POST /api/v1/transport-drivers/login`. A driver session is saved through `DriverStore.applySession` and opens `DriverShell`; a pending or rejected application shows the driver's own message; any other failure still reports the rider error, so a wrong password reads the same as before.
- Google sign-in follows the same rule: the rider call first, then the driver call, then `DriverShell`.
- A successful rider sign-in clears a stored driver session (`DriverApi.clearSession`), so the next launch does not jump into the driver shell, and the rider token is untouched by the driver path.
- The register link opens a dialog — **Register as Rider** → `RegisterScreen`, **Register as Driver** → `DriverRegisterScreen`. Both forms return to this login when they finish. The existing **Company Transport Driver sign in** button and `TransportDriverLoginScreen` were left as they were.
- `rider/splash/splash_screen.dart` now checks `DriverApi.hasToken()`: a saved driver token opens `DriverStartScreen`, which confirms it with `GET /me`, and everyone else still gets the login screen. Every driver sign-out and session-expired path now returns to the shared login instead of the driver login.
- `main.dart` uses `VendoTheme.light()` (the driver theme: same palette, same Poppins metrics, richer component styling) so pushed driver routes keep their look.

### Dead code and the standalone project

- `lib/driver/auth/screens/driver_login_screen.dart` (1,799 lines, including the application-status sheet) had no remaining references and was deleted. `driver_start_screen.dart` was kept: the splash still uses it for session restore.
- `vendo_driver/` was deleted afterwards (183 tracked files, recoverable from history). Before removing it: every file under its `lib/` had a same-named twin in `vendo_rider/lib/driver` apart from the deleted login screen and its own `main.dart`, its manifest permissions (`CAMERA`, `INTERNET`) are a subset of the Rider's, and no script, Gradle file or CI config referenced the project.

### Verified

- `flutter analyze` in `vendo_rider`: 65 issues, all the pre-existing infos/warnings both apps already had (`package:flutter/material.dart` deprecations, unused palette constants), no errors.
- `flutter build apk --debug --dart-define=VENDO_API_BASE_URL=http://192.168.1.17:8001/api/v1/rider`: succeeded, installed on the Infinix X6831.
- Temporary widget checks (written, run, then deleted) confirmed the register link opens the dialog with both choices, Cancel closes it, and each choice pushes its own registration form.
- Not run: a real rider or driver sign-in, the driver shell against live data, or Google sign-in. The owner tests on the device.

### Known gaps

- The driver Google sign-in still needs an Android OAuth client for the package the merged app ships under; the existing client is registered for `com.example.vendo_driver` (see `lib/driver/core/config/google_auth_config.dart`). `vendoph.rider` is the package that must carry the SHA-1.
- The driver's "Check application status" sheet lived in the deleted login screen, so there is currently no way to read an application decision without signing in.
- The Rider app still has no session restore of its own; only driver sessions reopen.
- `vendo_rider/android/` still carries the uncommitted built-in Kotlin migration from the earlier toolchain work; it is not part of this change.
