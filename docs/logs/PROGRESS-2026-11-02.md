# Progress — 2 November 2026

## Driver trips connected to the transport-driver API

- `vendo_driver/lib/core/api/driver_api.dart`:
  - New `trips()` reads `GET /api/v1/transport-drivers/trips`.
  - New `departTrip(id)` and `arriveTrip(id)` post to `/trips/{id}/depart` and `/trips/{id}/arrive` and return the trip the server saved.
  - `me()`, the trip calls and `logout()` now share one signed-in path (`_authorizedGet` / `_authorizedPost` / `_authorizedBody` / `_authHeaders`). A `401` clears the stored session before the exception reaches the screen, so an expired token cannot sit in secure storage.
- `vendo_driver/lib/core/data/driver_store.dart`:
  - `DriverTrip` gained `id` (the web id, used by the trip actions) and `tripType`. `isLive` is true for a trip that came from the API.
  - New `refreshTrips()`: loads the board, replaces the list, and records `tripsAreLive`, `tripsSyncedAt`, `tripsError` and `sessionExpired`. A second call while one is running is ignored, so the start-up load and a pull-to-refresh cannot race.
  - New `_tripFromApi()`, which maps `origin` / `destination` / `vehicle` / `manifest` / the schedule fields and the new scan counts. A trip with no schedule falls back to its departure time, then to now.
  - `depart()` and `arrive()` are now `Future<String>`. A live trip is changed on the server and the answer replaces the local trip; the server's refusal text is returned unchanged. Sample trips keep the old local rules so the demo still works offline.
  - `simulateDestinationScans()` ignores live trips, whose counts come from the station's scans.
- `vendo_driver/lib/features/dashboard/screens/driver_shell.dart`: loads the board once when the shell opens, after the start screen has restored the profile.
- `vendo_driver/lib/features/trips/screens/driver_dispatch_screen.dart` and `driver_handover_screen.dart`: await the depart/arrive calls. The blocked sheets now take the server's reason: the dispatch sheet switches its title from *Departure blocked* to *Trip not departed* and drops the "ask hub staff to scan" advice when the failure was not about scans; the handover sheet does the same with *Receiving not complete* → *Trip still open*. The handover sheet hides **Demo: simulate station scans** for a live trip.
- Distance: the trip API sends no route length, so `driver_trip_details_screen.dart` says *Not shared by the hub* and the trip status screen shows `—` instead of `0 km`.

## Refreshable driver home and quick actions

- `vendo_driver/lib/features/dashboard/screens/driver_home_screen.dart`:
  - The list is wrapped in a `RefreshIndicator` with `AlwaysScrollableScrollPhysics`, so pulling down anywhere on Home reloads the board.
  - New `_SyncStrip` under the licence notice: a green tick and *Updated 4 min ago from Vendo* with a **Refresh** button when the board is live; a spinner and *Loading the trips your hub assigned…* on the first load; a plain note that the trips are samples before the first successful load; and a red `NoticeCard` with **Retry** when the refresh failed. An expired session shows **Sign in**, which revokes the token and opens the sign-in screen.
  - New `_QuickActions` row under the stats: **Manifest**, **Dispatch** and **Trip status**, each aimed at the current trip with a one-line hint (`12 parcels`, `6 to scan`, `After departure`). An action that does not fit the trip's stage stays visible but disabled with the reason, so nothing is hidden.
  - The current trip card keeps one full-width primary button and the *Trip details* link; the duplicate Manifest button moved into the quick actions row.
- Web: `TransportDriverApiController::tripPayload()` now sends `origin_scanned` and `destination_scanned`, counted from the same `OrderFacilityStop` rows the workflow checks, so the progress bars on Home and the handover screen show real station scans.
- Docs: `docs/features/driver-app.md` has a new *Trips from the web* section with the payload table, the refresh triggers and the sample-trip fallback, and the Known gaps list no longer claims the trip screens are demo-only.

**Verified:** `flutter analyze lib` → No issues found (whole app, not just the changed files). `dart format` on the changed files. `php -l` on the controller → no syntax errors.

**Not run:** no device run and no widget test (owner does device testing), and no HTTP round-trip against the API, so the new payload fields and the depart/arrive responses were only checked against the controller code.

**Known gaps**

- Earnings still reads the legacy demo credits.
- The board lists scheduled and in-transit trips only; completed trips leave on the next refresh and there is no trip history.
- No route distance from the API yet.
- The manifest screen lists the trip manifest, but there is no live per-parcel scan feed, so the parcel list can lag behind the counts until the next refresh.
