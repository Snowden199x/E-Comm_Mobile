# 3 November 2026

## Rider profile: Personal Information, Vehicle Details, Change Password

- Split the three Account rows on the Rider Profile screen into real screens: `personal_information_screen.dart`, `vehicle_details_screen.dart`, and `change_password_screen.dart` under `vendo_rider/lib/features/dashboard/screens/`, sharing `widgets/profile_ui.dart` (Vendo palette, dark header, section cards, info rows, notes, status pill, loading and error cards).
- Personal Information shows identity, contact, home address, and Station Hub assignment from the signed-in Rider's approved record; Vehicle Details shows vehicle type, plate number, hub, service-area barangays, and whether the private licence and OR/CR copies are on file; Change Password validates the current and new password and submits them, keeping this device signed in.
- Added `RiderApi.riderProfile()` (`GET /api/v1/rider/profile`) and `RiderApi.changePassword()` (`PUT /api/v1/rider/profile/password`).
- Web repo: new `App\Http\Controllers\Api\RiderProfileController` returns only the authenticated Rider's own record and updates their password after `Hash::check`; two routes were added to the authenticated `v1/rider` group. No schema change and no migration.
- The screens never return the stored document images and never invent data: missing values read "Not on file", and a note points the Rider to the Station Hub for corrections because the mobile app has no editable profile fields.
- The Profile header now shows the account's profile picture from `GET /api/v1/rider/profile` when the web account has one, and keeps the neutral rider icon when there is no photo or the image fails to load. The photo is the public account image, not one of the private verification documents.
- Personal Information now has an Edit mode for the mobile number and home address (street, barangay, municipality/city, province, ZIP) with per-field validation, an inline save state, and the server error shown above the save button. It saves through `PUT /api/v1/rider/profile`, which updates only those fields on the Rider and courier record. Name, birthday, vehicle, documents, and the Station Hub assignment stay hub-managed; the screen says so, and saving an address does not move the Rider to another hub.
- Personal Information's Edit mode now covers only the full name (first, middle initial, last) and birthday, with a date picker and per-field validation. The name is written to the user and courier records, and the cached header name is refreshed so the Profile tab does not keep the old name. Phone, email, home address, and assignment are read-only again and point the Rider to the Station Hub.
- Riders can set a profile picture: tapping the avatar or **Change photo** opens a camera/gallery sheet, uploads through new `POST /api/v1/rider/profile/photo`, and the header updates immediately. Photos go to public `profile-pictures/riders` storage and replace the previous file; the private licence and OR/CR images are unaffected. `ProfilePhotoService` was not reused because it only accepts buyer, seller, and logistics-center roles, so the Rider path stays in `RiderProfileController`.
- Not verified on a device: needs an approved Rider token and an account with a profile picture against the updated API.
