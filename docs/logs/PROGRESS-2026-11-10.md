### What the pull added

- **Splash animation** (`lib/features/splash/splash_screen.dart`). The old 1.2s logo fade is replaced by an 8.2s `CustomPainter` story: a person walks to a vending machine, inserts a coin, the Vendo logo drops out, the person grabs it and throws it at the camera, then the logo and brand reveal. Only the logo is a bundled image; everything else is drawn, so no new package. A second controller loops a gentle pulse/float. After the timeline (`whenComplete`) the app checks `BuyerApi.hasToken()` and replaces the route with `HomeScreen` or `LoginScreen` after a 700ms hold and a 500ms fade. There is no skip and the splash always runs in full.
- **Notification tab is now wired.** The tab was a placeholder; `HomeScreen` now builds `NotificationsScreen(isActive: _currentIndex == 2)`. The screen is API-backed (`GET /notifications`, `filter=unread`, and `POST /notifications/{id}/read`), has All/Unread tabs with a count and Mark all read, groups parcel-progress updates separately from plain notifications, marks a row read when opened, polls every 30 seconds while active, and falls back to the cached page with an offline banner. Mark-all-read is queued when offline.
- **`buyer_api.dart`:** notification feed/unread count with per-page offline caching; `markNotificationRead`; `orders(status, group)` cache keys per status and group; `updateAccount(...)` that only sends the fields a screen owns, so Personal Information and Delivery Address cannot overwrite each other; shared buyer avatar read/write used by the Profile header.
- **Screen redesigns in the same commit:** product detail (`api_product_screen.dart` — hero gallery with photo dots, discount badge, variant selection, shop card, expandable description/specifications, share strip, related products, sticky add-to-cart bar), seller/shop page (`api_seller_screen.dart` — gradient header with in-shop search, banner from the shop's first product, two staggered card columns matching Home), Saved (`saved_screen.dart` — same two-column card grid and header as Home, heart removes), Notifications and Orders (group tabs plus a star picker for rating a completed order's item).
- No new dependency and no `pubspec.yaml` change.

## Rider app: first Android release build

The Rider app was release-unready: `com.example.vendo_rider`, release signed with the debug key, label "Vendo Xpress", `1.0.0+1`, no keystore. It is now configured for a public APK.

- **Identity.** `applicationId` and `namespace` are `vendoph.rider`, the launcher label is "Vendo Rider", `MainActivity` moved to `android/app/src/main/kotlin/vendoph/rider/`, and the version is `1.0.0+2`.
- **Icon.** `assets/images/app_icon.png` (1024px, white tile) and `app_icon_foreground.png` (transparent, inside the adaptive safe zone) are generated from the web brand icon `E-Comm_Web/public/images/logo/vendo-icon.png`. `flutter_launcher_icons` now points at them and also emits the adaptive icon (`colors.xml`, `mipmap-anydpi-v26`), replacing the old `rider_logo.jpg` source.
- **Signing.** New keystore `android/app/upload-keystore.jks` with `android/key.properties` (alias `vendo-rider`), both gitignored. `build.gradle.kts` reads `key.properties` and signs releases with it, falling back to the debug key when the file is absent so a fresh clone still runs `flutter run --release`. `apksigner` confirms the APK is signed by `CN=Vendo Rider`, not the debug key.
- **Login.** The rider form now falls back to the Transport Driver endpoint when rider login returns `401`, so one form accepts both account types: an approved rider opens the dashboard, an approved driver opens the trips screen, and a pending or rejected driver sees the server's reason. The existing "Transport Driver" link is unchanged.
- **Build.** Flutter 3.47.9 with Android SDK 36 (installed: platform 36, build-tools 36.0.0, CMake 3.22.1) and a local JDK 21 in `vendo_rider/.tooling/` (gitignored) because Gradle 8.14 rejects the system Java 25. Output: universal `app-release.apk` 107 MB, arm64 46.6 MB, armeabi-v7a 38.1 MB, x86_64 49.6 MB. Universal SHA-256 `f24bba19…826d5`.
- **Distribution.** GitHub Releases, asset name `vendo-rider.apk`. The web landing button and QR go through `https://vendo-ph.app/logistics/get-the-app`, which now redirects to `releases/latest/download/vendo-rider.apk`; the asset link stays valid across versions.

Details, commands, certificate fingerprints and the Play migration path: [rider app release](../features/rider-app-release.md).

**Verified:** `flutter analyze` on the changed login screen (only the file's pre-existing unused-field warning); release build succeeds; `aapt2 dump badging` shows `vendoph.rider`, `versionName 1.0.0`, `versionCode 2` (universal), label "Vendo Rider", and all three ABIs; the launcher PNG extracted from the APK is the Vendo mark; `apksigner` shows the release certificate. **Not verified:** no installation on a physical phone, no login with a real rider or driver account, no download test from GitHub (the release asset is not uploaded yet), no Google sign-in on a release build.

**Known gaps:** Google sign-in needs the release SHA-1 registered; Play is not set up; the universal APK is heavy on mobile data; no auto-update.
