# Progress — 12 November 2026

## Rider Android build toolchain upgrade (Gradle 9 / AGP 9 / Kotlin 2.4)

`flutter run` on `vendo_rider` failed before any Dart code was compiled. The machine has Flutter 3.50.0 (Dart 3.14.0), whose Flutter Gradle plugin rejects the project's old Android toolchain:

- `Your project's Gradle version (8.14.0) is lower than Flutter's minimum supported version of 9.3.1`
- after upgrading Gradle, `Android Gradle Plugin version 9.1.0 ... minimum supported ... 9.1.1`

`vendo_buyer` still has the same old settings; only `vendo_rider` was changed here, and its Dart/Android app code, manifest, signing, Firebase config and `google-services.json` are untouched.

### Changed files (`vendo_rider/android/`)

- `gradle/wrapper/gradle-wrapper.properties` — Gradle `8.14` → `9.5.0` (Flutter's current recommendation; 9.3.1 is the hard minimum but already logs a "soon to be dropped" warning).
- `settings.gradle.kts` — `com.android.application` `8.11.1` → `9.1.1` (Flutter 3.50 minimum), `org.jetbrains.kotlin.android` `2.2.20` → `2.4.0`. `com.google.gms.google-services` stays at `4.4.3`.
- `app/build.gradle.kts` — the `android { kotlinOptions { jvmTarget = ... } }` block is no longer valid under AGP 9 / Kotlin 2.4, so it was replaced with a top-level `kotlin { compilerOptions { jvmTarget = JvmTarget.JVM_17 } }` block, matching `vendo_driver`. The rest of the file (namespace `vendoph.rider`, signing config, release build type, `flutter.source`) is unchanged.
- `gradle.properties` — `org.gradle.jvmargs` lowered from `-Xmx8G -XX:MaxMetaspaceSize=4G` to `-Xmx3072m -XX:MaxMetaspaceSize=1024m -XX:ReservedCodeCacheSize=256m`. On this 7 GB-RAM machine the 8 GB heap made the Gradle daemon die mid-build ("insufficient memory ... Native memory allocation (mmap) failed").

### Verified

- `flutter build apk --debug --dart-define=VENDO_API_BASE_URL=http://192.168.1.17:8001/api/v1/rider` in `vendo_rider`: succeeded in ~461 s on this machine and produced `build/app/outputs/flutter-apk/app-debug.apk` (214 MB, debug). The JVM crash log `android/hs_err_pid*.log` was removed.
- Not run: install/launch on the Infinix X6831, `flutter run` with hot reload, release build or `flutter analyze`. The owner tests on device.

### Known gaps / next steps

- Flutter 3.50 still logs forward-looking warnings: AGP should reach 9.3.1 and Kotlin 2.4.20 eventually, and the app + `firebase_core` still apply the Kotlin Gradle Plugin instead of the new built-in Kotlin. These are warnings only today.
- `vendo_buyer` still uses Gradle 8.14 / AGP 8.11.1 and will hit the same minimum-version error when built with this Flutter SDK.
- `gradle.properties` memory limits are shared project config; a machine with more RAM can raise them, but the reduced values build fine here.
- `vendo_driver/android` is unchanged (Gradle 9.3.1 / AGP 9.1.0 / Kotlin 2.4.0), which is below this Flutter's AGP minimum; it will fail the same check until bumped.
